2. Comparativo: Estado Atual vs. Estado Desejado

Componente / Requisito Estado Atual (Problema) Novo Estado (Solução)
Versão do Solr solr:9.8.0 solr:9.11.0 oficial com gosu instalado
Core oai Cópia independente e defasada em Docker/solr/cores/oai (usa LUCENE_42 e tipos obsoletos Trie*Field) Obtido diretamente de lareferencia-oai-pmh/solr.core/oai (usa *PointField e versão moderna)
Core biblio Cópia com patches manuais injetados no Docker (campo vector e knn_vector adicionados manualmente) Obtido diretamente de vufind/solr/vufind/biblio de forma inalterada. Suporte vetorial fornecido pelo próprio repositório VuFind quando ativo.
JARs Auxiliares Baixados via wget da branch master do GitHub (risco de divergência de versão) Obtidos do mesmo checkout selecionado em vufind/solr/vufind/jars/
Governança de Versão Arquivos de configuração rastreados no Git sob Docker/solr/cores Docker/solr/cores removido do Git; diretório puramente transitório de staging (ignorado no .gitignore)
Atualização de Configuração Bloqueada por .lr_initialized. Modificações em templates nunca chegam ao volume persistente. Comando explícito update-config: gera backup em conf.bak.*, sincroniza novo conf/ e preserva 100% dos dados de índice.

3. Fluxos de Execução do Entrypoint

O comportamento do Docker/solr/entrypoint.sh agora distingue claramente uma instalação nova de uma atualização de volume existente:

Inicialização Limpa vs. Atualização Explícita (update-config)
sequenceDiagram
    autonumber
    actor Dev as Operador / Script
    participant EP as entrypoint.sh
    participant Template as /opt/lr-solr-cores
    participant Vol as /var/solr/data
    participant Solr as Processo Solr (8983)

    alt Caso A: Fresh Install (Volume Vazio)
        Dev->>EP: docker compose up -d solr
        EP->>Vol: Verifica existência de .lr_initialized
        Note over EP,Vol: Marcador ausente
        EP->>Template: Copia cores oai e biblio
        Template-->>Vol: Instalação inicial em /var/solr/data/{biblio,oai}
        EP->>Vol: Grava .applied_config_info e toca .lr_initialized
        EP->>Solr: Inicia Solr (exec gosu solr solr start)
    else Caso B: Atualização Explícita (update-config)
        Dev->>EP: ./Docker/docker.sh solr update-config
        EP->>Vol: Localiza cores existentes
        loop Para cada core (biblio, oai)
            EP->>Vol: cp -a conf/ conf.bak.TIMESTAMP
            EP->>Vol: Atualiza conf/ a partir de /opt/lr-solr-cores/{core}/conf/
            Note over EP,Vol: Pasta data/ (Índice Lucene) NÃO É TOCADA!
            EP->>Vol: Atualiza core.properties e metadata
        end
        EP->>Vol: Atualiza /var/solr/data/jars/ e /import/
        alt Se Solr estiver ativo
            EP->>Solr: curl RELOAD em /admin/cores?action=RELOAD&core={core}
            Solr-->>Dev: Cores recarregados com novo schema sem downtime
        else Se Solr estiver desligado
            EP-->>Dev: Notifica pronto para próximo start
        end
    end

4. Etapas Detalhadas de Execução

Fase 1: Limpeza do Repositório Git e Ajuste do .gitignore

1
  • Executar git rm -r Docker/solr/cores/biblio Docker/solr/cores/oai para desvincular as cópias órfãs.
  • Atualizar Docker/.gitignore para ignorar os diretórios de staging de cores e JARs (preservando .gitkeep).
  • Garantir que .dockerignore continue ignorando a pasta vufind raiz, mas permita os arquivos estagiados em Docker/solr/.

Fase 2: Mecanismo de Staging & Trazabilidade

2
  • Implementar função compartilhada prepare_solr_staging no docker.sh e docker-dev.sh.
  • Garantir que os checkouts de lareferencia-oai-pmh e vufind estejam prontos antes do build/up do Solr (mesmo sem vufind-web).
  • Sincronizar oai de lareferencia-oai-pmh/solr.core/oai para Docker/solr/cores/oai.
  • Sincronizar biblio de vufind/solr/vufind/biblio para Docker/solr/cores/biblio (cópia 100% fiel, sem patches).
  • Sincronizar JARs de vufind/solr/vufind/jars e importadores de vufind/import.
  • Gerar arquivo Docker/solr/cores/build-info.properties registrando versão do Solr, repositórios de origem e commit hashes.

Fase 3: Atualização do Dockerfile para Solr 9.11.0

3
  • Alterar base para FROM solr:9.11.0.
  • Instalar o pacote gosu via apt-get no ambiente Ubuntu Jammy do Solr.
  • Remover os comandos wget da branch master do GitHub (usando diretamente os JARs do checkout local).
  • Manter a ativação do módulo oficial analysis-extras (já integrado no Solr 9.11.0).

Fase 4: Procedimento de Inicialização e Atualização Segura

4
  • Aprimorar Docker/solr/entrypoint.sh com suporte à rotina update-config e variável SOLR_UPDATE_CONFIG=true.
  • Criar backup automático das configurações antigas em conf.bak.<timestamp>.
  • Garantir preservação irrestrita do diretório data/ dos cores.
  • Disparar recarga a quente dos cores via API CoreAdmin do Solr (/solr/admin/cores?action=RELOAD).
  • Adicionar comandos CLI de fácil uso: 
    # Fluxo Normal
./Docker/docker.sh solr update-config

# Fluxo de Desenvolvimento
./Docker/docker-dev.sh solr update-config

Fase 5: Documentação Operacional & Diretrizes de Reindexação

5
  • Documentar o procedimento de atualização em Docker/README.md e docs/.
  • Instruir sobre a migração de Trie*Field para PointField no core oai: após atualizar o schema, os registros persistidos no banco do Harvester podem ser reindexados pelo painel ("Index" / run_task index).

Fase 6: Validação Completa & Critérios de Aceite

6
  • Confirmar que o container Solr roda sob a versão 9.11.0 (solr --version).
  • Verificar que o core oai utiliza exclusivamente o schema e configurações do provider OAI-PMH.
  • Verificar que o core biblio corresponde exatamente ao VuFind sem injeções manuais no Docker.
  • Testar indexação com o Harvester, consultas na interface web do VuFind e fornecimento de registros via OAI-PMH.
Nota de Preservação de Dados: O procedimento update-config foi projetado para garantir que a pasta /var/solr/data/{core}/data nunca seja removida ou sobrescrita, permitindo atualizar esquemas e configurações com segurança máxima.
